# 安心用药：Web MVP 架构与开发方案

## 交付范围
当前交付为可直接打开的 HTML 交互原型，使用浏览器本地存储，同源双标签页通过 storage 事件同步。不包含线上数据库、真实账号、真实 OCR 或跨设备同步；上传识别明确使用演示结果。所有药品数据仅用于交互演示。

正式 MVP 使用 React + TypeScript + Vite，后端采用 Supabase 的 PostgreSQL、Auth、Storage、Realtime 和服务端函数。部署前核验平台可用性、成本和区域；数据层使用接口隔离，便于替换服务商。当前不创建付费资源、不发布、不接入真实患者数据。

  data/                   repository 接口、云端适配、订阅与重连

## 模块和流转
登录 → 老人同意家庭绑定 → 手动录入或上传识别 → 核对草稿 → 启用计划 → 服务端生成单次任务 → 老人网页提示 → 确认/跳过/稍后 → 数据库事务保存 → Realtime 通知两端重新读取 → 亲属查看与发送提醒。

说明书不自动生成个人剂量；必须补齐并核对。计划未启用不生成任务。已读消息不等于服药。超时未确认不等于漏服。

## 服务端接口契约
- create_plan(reviewedDraft)：验证字段及修改权限，事务保存计划。
- update_plan(planId, expectedVersion, input)：创建新版本，取消受影响未完成任务；不改历史快照。
- generate_tasks()：滚动生成未来 7 天任务，唯一约束保证定时重复运行不重复创建。
- record_dose(taskId, action, operationId, expectedRevision)：确认/跳过/稍后/撤销，事务写事件并更新状态；冲突返回最新版本。撤销引用原事件，不能撤销别人的有效确认。
- send_reminder(taskId, operationId)：验证绑定、状态和冷却时间；写消息，不把消息写成服药记录。
- check_overdue()：服务端每分钟按原计划时间和宽限期检查任务；稍后只改变提醒时间，不改变计划时间。
- analyze_image(draftId)：服务端调用 OCR，密钥不进入前端，返回草稿和原文定位。

## 同步、权限与失败处理
数据库为最终来源，Realtime 仅通知重新读取。初次加载和重连均重取数据，订阅事件防抖刷新。每次操作等待服务端成功后展示成功；失败保留界面并提示重试，operation_id 保证重试去重。第一版不支持离线写入，离线时禁用提交并明确状态，避免给亲属误报。

所有表启用 RLS：老人仅访问自己数据；亲属仅访问已同意且有效绑定的老人数据；编辑计划需单独权限。角色切换不能绕过权限。Service role 密钥仅位于服务端。解绑立即失去访问权限并关闭订阅。

网页打开时显示提醒，不承诺后台、休眠或关闭网页后的通知。声音需用户手势启用。消息恢复时过滤已完成任务，确认后其他标签页关闭对应提示。

## 开发顺序与验收
1. 原型：老人/亲属视图、今日卡片、添加核对、确认撤销、跳过、稍后、发送提醒、历史、设置、演示控制。
2. 云端基础：认证、建表、RLS、邀请同意、私有文件存储。验收未绑定访问被拒、解绑立即失权。
3. 用药闭环：计划版本、任务生成、记录事务、网页提醒。验收跨日、结束日期、停用、重复请求、双端并发。
4. 实时协同：订阅、重连、亲属消息、冷却时间。使用两个独立账号在不同浏览器验证刷新后数据保留及跨设备同步。
5. OCR：先打印处方和说明书，失败转手动；缺少剂量不能启用。用脱敏且有标准答案的样本评估字段准确率。
6. 发布准备：键盘与大字体检查、窄屏检查、错误提示、数据库备份和演示数据隔离。

## 本次原型检查

### 计划表单更新
药品名称旁增加可编辑类型，内置 MEDICINE_CATALOG 精确匹配通用名与明确别名；目前含 7 种药品。无匹配时手动填写，感冒药等类型允许自定义。分类参考 NHS 药品资料：https://www.nhs.uk/medicines/amlodipine/ 、https://www.nhs.uk/medicines/losartan/ 、https://www.nhs.uk/medicines/metformin/ 、https://www.nhs.uk/medicines/statins/ 、https://www.nhs.uk/medicines/paracetamol-for-adults/ 、https://www.nhs.uk/medicines/antihistamines/ 。分类仅作整理标签，不推断个人适应症。

移除规格输入；每日提醒使用可添加、移除的 time 控件，禁止重复时间。疗程选择 days 或 quantity，可留空。保存 courseMode、courseValue、totalDoses 和派生 end。天数乘每日次数得到总次数；总量除每次用量得到完整次数，余量单独显示，不自动加量或生成半剂。总量单位沿用每次用量单位。最后一天只生成剩余次数，按时间先后排列。长期用药不设次数上限。编辑已有计划可恢复上述字段；历史数据仍保留。

使用本地 HTTP 服务打开可以测试同源双标签同步；file 模式主要用于单页演示，各浏览器对本地存储行为不同。原型的身份切换仅用于展示，不构成认证或访问控制。正式项目必须先完成云端权限再使用真实数据。
